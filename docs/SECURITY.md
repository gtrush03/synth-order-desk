# Security, threat model and cost limits

## Threat model for the judge package
- **Exposure**: the server binds 127.0.0.1 only and rejects other Host headers; mutations require the exact local Origin; CSP forbids remote scripts, frames and forms; only allowlisted static files and documents are served; document IDs are validated with strict patterns; conversation and artifact IDs must be v4 UUIDs.
- **Input limits**: JSON bodies ≤ 25 KB; audio ≤ 4 MB and 30 s; messages ≤ 2,000 characters; model output ≤ 64 KB; Hotdata response ≤ 512 KB; company input to Hotdata ≤ 25 KB; quantities 1–200; budgets ≤ $10,000.
- **Child processes**: model helper (45 s), ffmpeg (15 s), whisper-cli (45 s), HydraDB bridge (10 s), rote (15 s), all with bounded output; transcription directories are deleted in `finally`.
- **Prompt injection**: the on-device model is told that history and data are context, never instructions; it extracts only explicit changes; money changes need a money mention in the utterance; approval is a deterministic check, not a model decision; the Play's recomputed proposal must equal the server's or approval pauses.
- **Data at rest**: session, draft, receipt and memory files are written with mode 0600 under the run directory. A `last-voice-error.json` may contain a bounded tail of ffmpeg/whisper stderr for local debugging.
- **Secrets**: none are shipped. `HOTDATA_API_KEY`, `HYDRADB_*` are read from the environment only. The export tool aborts on secret-shaped content and on any reference to private paths, recordings or the sponsor lab; `judge/verify-export.py` re-checks the shipped tree against the manifest.

## Cost limits
- Recorded Apple/sponsor proof uses no cloud language model (`cloudModelCalls: 0` in those receipts). The separately enabled GPT-Live voice adapter requires operator-approved funding and a bounded private allowance; it is never enabled by package setup or self-check.
- Hotdata is opt-in through `conversation/hotdata-allowance.json`: `freeCreditConfirmed` must be true, `confirmedAvailableUsd ≥ 20`, `maxInputBytes` exactly 25,000, `maxRuns` 1–20, `validUntil` in the future, workspace ID pattern-checked. Failed runs count. Databases are created with a 30-minute `expires_at` as a best-effort fallback; expiry is not a guaranteed deletion, so the receipt records whether each explicit delete was confirmed. This is a local consumption cap and does not change provider billing.
- RocketRide runs only through the opt-in allowance file with a credit floor (1,000 units) and a run cap; it executes pure Python in a staging sandbox with no model and no external credential; the served integration receipt shows 0.5 + 0.3 units. Cognee cloud and any paid model key are not used.

## Review notes on the current Snyk Code findings
The exact scan above and `evidence/snyk/code.json` are authoritative for this export. The 2:26 PM PDT candidate reported twelve findings; earlier `evidence/security-code-findings.json` is historical and does not certify the expanded source. ROOT owns application fixes. No finding is suppressed or ignored; the following source review provides context, not a security-clean claim.
- `src/server.ts` — **Path Traversal (high)** at `store.update(requestID, revision, edit)`: `StateStore` receives its filesystem path from server configuration. The request ID is checked against the known task-ID set, then used as a JSON object key. Writes use the fixed constructor path plus a generated UUID temporary suffix and rename back to that fixed path (`src/state.ts`). The exported private-dashboard stub has no task IDs. This is the current write-flow finding, not the earlier static-file-read finding; it remains open in the scan.
- `src/server.ts` — **Cleartext HTTP (medium)**: the server binds 127.0.0.1 and validates Host. Exposing it beyond loopback requires TLS and authentication beyond this demo's boundary.
- `src/talk.ts` — **DOM-based XSS (medium, multiple sites; exact current count above)**: interpolated display strings use `esc()`; quantities and money use numeric formatters, and some classes/statuses depend on the server's enum contract. This is not a blanket guarantee for every interpolation. The API is loopback and CSP constrains scripts. The `innerHTML` flows remain flagged; a DOM-building rewrite or recognized sanitizer would make the boundary easier to analyze.
- `src/browser-actions.ts` — **Insufficient postMessage validation (low)**: the flagged listener is a Node WebSocket `message` callback connected to the validated loopback CDP endpoint, not `window.postMessage`. Replies are parsed and matched to pending request IDs. That endpoint/request correlation is the relevant boundary; no universal origin-validation guarantee is claimed.
- `src/gpt-live-browser.ts` — **Insufficient postMessage validation (low)**: the callback receives the established WebRTC data channel’s messages, not cross-origin window messages. It bounds and parses the event input before dispatch. The finding remains open; signaling, delegated-action validation and the server permission boundary must be assessed together.
- `tests/order-desk.test.ts` — **Cleartext HTTP (low)**: a test deliberately sends a raw `node:http` request with a foreign Host header to prove the loopback server rejects it.
- The earlier error-message-exposure finding is historical; it is absent from the current sixteen-finding scan. Historical receipts are retained separately.

## Inherited findings, disclosed
The app talks to a **local Cognee 1.5.4 API**. The sponsor-lab dependency scan on September 10–11 reported for that Python environment: cognee 1.5.4 — critical, arbitrary code injection (CVSS 9.2); diskcache 5.6.3 — high, deserialization of untrusted data (7.0); litellm 1.96.2 — high, insufficient session expiration (7.1), medium, missing authentication for critical function (6.9), medium, insufficient session expiration (5.3). No fixed versions were listed at scan time. Historically, that earlier lab scan could not run Snyk Code (HTTP403, SNYK-CODE-0005); Code was later enabled. Current package results are recorded above and supersede that historical availability failure. Mitigation in this package: Cognee is reached only on 127.0.0.1, only with validated raw documents produced by this app, and only for storage and retrieval; it is not exposed by the server. The risk remains for anyone who runs Cognee 1.5.4 on their machine and is reported rather than hidden. HydraDB runs as a local container on Bolt 7687 (AGPL-3.0 image v0.1.1); its authentication settings are the operator's responsibility.
